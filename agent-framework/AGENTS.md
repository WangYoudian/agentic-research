# Agent Framework 研究说明

## 目的

本目录收集了一批不同方向的 agent 项目源码与研究材料，用于比较不同 agent 实现的思路、定位与工程设计。后续会逐项阅读并归纳，不要求对每个项目做深入源码级分析，而是聚焦于它们的整体架构、目标用户、工作方式和工程取舍。

本目录当前包含的项目包括：

- pi
- Hermes Agent
- Claude Code
- Prime Agent
- DeepSeek Harness
- OpenClaw

## 研究目标

我们将遵循如下总体流程：

1. 先建立总览，了解每个项目的定位、技术路线和典型能力。
2. 再按项目逐项做高层分析，关注：
   - 它们解决什么问题
   - 它们是如何组织 agent runtime 的
   - 它们如何处理工具调用、任务执行、状态管理与扩展
3. 之后做 A/B 对比：
   - A 线：架构与工程设计视角
   - B 线：产品与使用体验视角
4. 最终整理成一份汇总分析报告，输出各项目的共性、差异和设计启发。

## A/B 对比框架

A 类比较关注：

- agent runtime 是怎么设计的
- 模块之间如何协作
- 工具调用、状态管理和任务编排是如何实现的
- 代码组织与工程抽象有哪些共性

B 类比较关注：

- 这个项目面向什么用户
- 它是开发工具、通用 agent 还是工作流系统
- 终端体验、扩展性和生态组成如何
- 设计目标和实际落地方式有什么差异

## 注意事项

- 本过程不要求深入具体 agent 的实现细节。
- 重点在于：快速建立项目地图、理解设计意图、识别不同 agent 范式。
- 后续每个项目的分析都应保持一致的观察维度，便于做横向比较。

## 后续分析顺序

建议按下面顺序逐项观察：

1. pi
2. Hermes Agent
3. Claude Code
4. Prime Agent
5. DeepSeek Harness
6. OpenClaw

在逐项分析结束后，统一对比各项目的：

- runtime 思路
- agent 角色设计
- 工具使用方式
- 扩展方式
- 目标用户与适用场景

## 输出目标

最终输出一份分析报告，内容包括：

- 每个 agent 项目的简要定位
- 项目间的结构差异
- A/B 对比结论
- 设计启发与研究建议

这份说明的目的，是为后续逐项分析和最终汇总报告提供统一框架与一致的观察视角。
